## Claim boundary (read this before using any number)

* Candidates are **basename-level** matches taken from `source_reuse_map.json`.
  The map itself states `identity_claim: none`; nothing here upgrades a
  basename match into a source-identity or build-version claim.
* `orig_matched` counts **names, not behaviour**.  A demangled name that occurs
  in both an object and ORIG's dynsym proves only that the same mangled name is
  defined in both binaries.  Symbol-name match is **NOT** behaviour identity:
  identical names can carry different logic, constants, call graphs or data.
* **No tag-394 equivalence is claimed.**  Nothing in this matrix compares code,
  instruction bytes or semantics against build 394; it only records what
  compiles with the c5root toolchain and which symbol names coincide.
* System headers come from the host (`/usr/include`, Ubuntu glibc 2.39), not
  from a 2009-era libc; the single CU that fails to compile here fails on
  exactly that (`scandir`'s comparator prototype changed).
* `local_total` counts names that appear only as file-scope (lowercase nm
  type letter) definitions in their object.  0 of the 1434 local-only names we
  produce also occur in ORIG's dynsym -- a name can be file scope in one build
  and exported in another -- while the rest cannot appear in any dynsym-based
  comparison, so `orig_matched` is bounded by each object's global names.

## Exact include roots that make each family compile

Pass 1 compiled with the full root list of the candidate's tree (the tree root
itself, its `include`/`import/include`, its `output/.../release/include` dirs,
the secagent equivalents, `third_party/import/include/{tencore,opensource}`).
Pass 2 then greedily dropped every root that the CUs of that tree did not need;
a root was only dropped when each test CU recompiled with the reduced list
**and produced exactly the same defined symbols** as with the full list, so a
dropped root cannot silently switch a header copy.  The reduced list was
re-verified that way on every CU compiled from the tree, and pass 3 rebuilt all
objects with it; `roots=full` in a `.res` file means that CU fell back to the
full list.  Raw lists: `reuse/log/_full_<tree>.roots` and
`reuse/log/_min_<tree>.roots`; per-CU ablation compiles:
`reuse/log/_roots_verify.log`.
