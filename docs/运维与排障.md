# 运维与排障

## 启停与存档（务必 TERM 优先）

- `df_game_r` 收到 **SIGTERM** 会把在线角色写库后退出；**SIGKILL（kill -9）会丢失上次自动存档之后的进度**。
  在线角色平时由游戏服按周期自动存档，下线时也会存档。
- 容器内：`/opt/remake/runtime/dnfctl.sh stop` 先 TERM 全部 game 并最多等 120 s，再按依赖倒序停其他服务；
  `dnfctl.sh restart-game 11` 只重启 siroco11；`dnfctl.sh status` 看进程。
- `docker compose stop` 会给容器 SIGTERM，入口脚本转交 `dnfctl.sh stop`；compose 里
  `stop_grace_period: 3m` 留足了存档时间。不要 `docker kill`。
- 有玩家在线时重启前先通知。

## TSS 反外挂共享内存（选角空槽/无字）

`df_game_r` 内的 TSS SDK 与 secsvr（gunnersvr / zergsvr / secagent）通过 POSIX 共享内存
`/dev/shm/sec_tss_sdk_bus_*` 通讯，三个条件缺一不可：

1. **同一个 IPC 命名空间**：Docker 镜像把它们放在同一个容器里，天然满足；若 game 与 secsvr 分在
   不同容器 / chroot，需要 `--ipc=host`（或 `ipc: shareable` + `service:`），chroot 前还要
   `mount --bind /dev/shm <chroot>/dev/shm`。
2. **`/dev/shm` 足够大**：compose 设了 `shm_size: 8g`（与上游一致，默认 64M 不够）。
3. **`LD_PRELOAD=libtss_shmfix.so`**（`dnfctl.sh` 已设置）：修正 SDK 传给 `shm_open` 的带 `/` 的名字，
   源码 `remake/runtime/libtss_shmfix.c`。

成功标志：game 日志 / `tss_sdk_*.log` 出现 `AntibotInterface::Initialize, rc=0`。失败时选角界面空槽、
没有字、“开始”点不了。

## 字符集（latin1）

游戏库约定把 UTF-8 字节按 **latin1** 存取（与 `df_game_r` 一致）。拍卖服 `df_auction_r` 与点券服
`df_point_r` 用自己的 libmysqlclient，必须同样用 latin1 连接，否则物主名等中文变乱码：
给它们单独的 `HOME`，放 `.my.cnf`：

```ini
[UseSQL]
default-character-set=latin1
```

`entrypoint.sh` 已为 `/home/neople/auction`、`/home/neople/point` 生成并以此为 HOME 启动。

## MONITOR_PUBLIC_IP

频道配置里的 `ip =` 与 monitor 下发给客户端的地址都来自 `PUBLIC_IP`（写入
`/data/monitor_ip/MONITOR_PUBLIC_IP`）。改 IP 后重启容器即可重新渲染频道配置。

## 常见问题

| 现象 | 排查 |
|---|---|
| 选频道后断开 / 连不上 | `PUBLIC_IP` 是否为客户端可达地址；30011/31011 等端口是否放行 |
| 选角空槽、无字 | 见上面 TSS 一节；看 secsvr 三个进程是否在、`/dev/shm` 下是否有 `sec_tss_sdk_bus_*` |
| 进城镇一直 Loading | 确认 `insert_game_world` 等发包路径没有残留调试跳过（必须走 ORIG 发包顺序） |
| `GLIBC_2.3x not found` | 现代路线产物只能跑在 glibc ≥ 2.38 的 i386 运行库上 |
| 启动报 `Table ... doesn't exist` | 补表到 `docker/mysql/initdb/remake-extra.sql.in`，已有库手动执行一次 |
| 拍卖行中文名乱码 | latin1 `.my.cnf` 未生效（HOME 不对） |
| 服务反复退出 | 看 `/data/log/<服务>.out` 与 `/home/neople/<服务>/log/Log*.error` |
