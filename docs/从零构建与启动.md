# 从零构建与启动

## 0. 需要准备什么

| 项 | 来源 | 是否入库 |
|---|---|---|
| 14 个服务的源码 | 本仓库 `remake/source` | 是 |
| GCC 4.x 工具链、32 位 zlib / OpenSSL | `toolchains/bootstrap.sh` 从 CentOS Vault / Debian 下载 | 否 |
| 配置模板、secsvr 原版 ELF、TSS SDK、`libnxencryption.so`、`Script.pvf`（`init/Script.tgz`）、初始 SQL（`init/init_sql.tgz`） | 子模块 `.origin_1031`（llnut/dnf 清风 1031） | 子模块引用 |
| 客户端、登录器 | 自备（llnut/dnf README 中的清风客户端与 [dnf-login](https://github.com/llnut/dnf-login)） | 否 |

想换 PVF：把自己的 `Script.pvf` 放到 dnf 容器的 `/data/Script.pvf`（数据卷 `dnf-data`）。

## 1. 获取代码

```bash
git clone --recursive https://github.com/LoyieKing/rednf.git
cd rednf            # 已有 clone：git submodule update --init .origin_1031
```

## 2. Docker 一键构建与启动

宿主：x86_64 Linux + Docker（含 compose 插件），内存 ≥ 4G，磁盘 ≥ 10G。

```bash
cp docker/.env.example docker/.env
vi docker/.env      # PUBLIC_IP=客户端能访问的 IP；改掉两个密码
docker compose -f docker/compose.yaml --env-file docker/.env up -d --build
```

过程：

1. **构建阶段**（`docker/Dockerfile` 的 `build`）：Debian 13 + `g++-multilib`，执行
   `toolchains/bootstrap.sh`，再 `cmake -S remake/source -B remake/build && cmake --build`，
   并编译 `remake/runtime/libtss_shmfix.c`。国内网络可在 `.env` 里设置
   `DNF_MIRROR=https://mirrors.tuna.tsinghua.edu.cn/centos-vault`。
2. **运行阶段**：Debian 13 + i386 运行库；放入 `.origin_1031` 的 `home/template`，再用 remake
   产物覆盖其中的 `df_*_r`。
3. **mysql 服务**（MySQL 5.7）首次启动时执行 `docker/mysql/initdb/10-dnf-schema.sh`：
   解开 `.origin_1031` 的 `init_sql.tgz`，按上游清单建库导入，再执行
   `remake-extra.sql.in` 补表（见 [数据库.md](数据库.md)）。
4. **dnf 服务** `docker/runtime/entrypoint.sh`：渲染配置模板（`SERVER_GROUP`、`DEC_GAME_PWD` 等占位符）、
   写 `MONITOR_PUBLIC_IP`、把容器内 `127.0.0.1:3306/3307` 转发到 mysql、更新 `d_taiwan.db_connect`、
   然后用 `docker/runtime/dnfctl.sh run` 按顺序拉起全部服务。

看日志：`docker compose -f docker/compose.yaml logs -f dnf`，各服务输出在容器 `/data/log/*.out`，
服务自身日志在 `/home/neople/<服务>/log/`。频道起来的标志是 `game/log/<频道>/Log*.init` 里出现
`Connect To Guild Server` / `Connect To Monitor Server`。

## 3. 环境变量（docker/.env）

| 变量 | 默认 | 说明 |
|---|---|---|
| `PUBLIC_IP` | 必填 | 写入频道配置与 `MONITOR_PUBLIC_IP`，**必须是客户端实际连接的 IP**，填错则选频道后连不上 |
| `DNF_DB_ROOT_PASSWORD` | 必填 | MySQL root |
| `DNF_DB_GAME_PASSWORD` | 必填 | `game` 账号密码，只取前 8 位；配置里存的是 `TeaEncrypt` 后的密文 |
| `SERVER_GROUP` / `SERVER_GROUP_NAME` | `3` / `siroco` | 大区；决定端口 `3xxxx` 与频道名 `siroco11` |
| `SERVER_GROUP_DB` | `cain` | 库名后缀：`taiwan_cain`、`d_channel_cain` … |
| `OPEN_CHANNEL` | `11,52` | 开启的频道 |
| `MYSQL_PUBLISH` | `127.0.0.1:3000` | MySQL 映射到宿主的地址 |

## 4. 端口

| 端口 | 协议 | 服务 |
|---|---|---|
| 7001 | tcp/udp | channel（客户端选频道） |
| 7200 | tcp/udp | relay |
| 7300 | tcp/udp | community |
| 2311-2313 | udp | stun |
| 30011 / 30052 | tcp | game siroco11 / siroco52（`SERVER_GROUP`00`频道号`） |
| 31011 / 31052 | udp | game P2P（`SERVER_GROUP`10`频道号`） |
| 7000 | tcp/udp | bridge（容器内部） |
| 30303/30403/30503/30703/30803/31003… | | monitor/guild/statics/coserver/auction/hades 等，容器内部 |

## 5. 账号与 GM

账号库是 `d_taiwan.accounts`（`UID`、`accountname`、`password`=MD5），角色库 `taiwan_<db>.charac_info`。
登录流程由登录器 + 登录网关完成：上游镜像使用 llnut 的 `dnf-gate-server` 与 `dnf-login`，
本仓库的 compose **暂未内置网关**（见“已知限制”）；可以：

- 直接沿用 llnut/dnf 的登录器方案，单独部署 `dnf-gate-server` 指向同一个 MySQL；或
- 使用会把账号/会话写入 `d_taiwan` 的其他登录器。

GM：上游的 `GM_ACCOUNT/GM_PASSWORD/GM_CONNECT_KEY` 用于 GM 工具连接 manager（端口见
`home/neople/manager/cfg`）；把账号设为 GM 需要在 `d_taiwan` 对应表授予权限（随登录器方案而定）。

## 6. 客户端连接

客户端用清风 1031 客户端；登录器里服务器地址填 `PUBLIC_IP`。客户端连 channel 的 7001 拿频道列表，
再直连 game 的 `30011/30052`。频道地址来自 `MONITOR_PUBLIC_IP`，所以 `PUBLIC_IP` 必须是客户端
看得到的地址（WSL / NAT 环境下尤其要注意，不能是 127.0.0.1）。

## 7. 不用 Docker

见仓库根 README 的“只构建二进制”。运行时可参照 `docker/runtime/*.sh`：把 `.origin_1031` 的
`home/template/neople` 复制为 `/home/neople`，替换 `df_*_r`，按 `dnfctl.sh run` 的顺序启动；
需要 i386 的 `libc6 libstdc++6 libgcc-s1 zlib1g`（GLIBC ≥ 2.38，现代路线产物不能放进 CentOS 7）。

## 8. 已知限制

- compose 里没有登录网关（`dnf-gate-server`），账号注册/登录需另行部署。
- `remake/secsvr` 的重建源码还没有一键构建脚本，运行时使用 `.origin_1031` 的原版 secsvr ELF。
- 上游的 DP 插件 / `libhook.so` / frida 钩子是给原版 ELF 用的，remake 镜像默认不加载。
